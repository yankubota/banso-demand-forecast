# 需要予測ダッシュボード（仮称）— P0 実装 v0.1.0

POS・レジのCSVを取り込むだけで「明日つくる数・発注する数」がわかる、ブラウザ完結の需要予測ダッシュボード。
仕様は **`spec.md` が唯一の正（SSOT）** です。本READMEは起動手順と実装上の注記のみを扱います。

- 対応仕様：spec.md v1.0（実装記録 v1.0.1 / ADD-01〜05）
- 技術：React 19 + Vite／JS + JSDoc／useReducer + Context／Vanilla CSS（OKLCHトークン）／外部ランタイム依存ゼロ
- データ：`localStorage`（キー接頭辞 `df_`）。**外部送信なし**

---

## 1. セットアップ（3コマンド）

```bash
npm install        # 依存の取得（react / react-dom / vite のみ）
npm run dev        # 開発サーバ起動 → http://localhost:5173
npm run build      # 本番ビルド → dist/
```

動作確認：起動後、ダッシュボードの「サンプルデータを読み込む」を押すと、菓子店を想定した約150日分のデータで
取込 → 予測 → 発注推奨 → 発注書CSV出力 まで一通り試せます（`public/sample_sales.csv`）。

ロジックのスモークテスト（Node単体・ブラウザ不要）：

```bash
node smoke.test.mjs
```

## 2. Vercel デプロイ手順

1. GitHubに新規**プライベート**リポジトリを作成し、本フォルダ一式をpush（`node_modules/`・`dist/` は `.gitignore` 済み）
2. Vercel → **Add New… → Project** → 当該リポジトリをImport
3. Framework Preset：**Vite**（自動検出。Build Command `npm run build`／Output `dist`）
4. **Deploy** を押すだけ（環境変数・サーバ設定は不要）

> R-1（知財分離）：本リポジトリはBanso独自資産です。センター事業の納品リポジトリとは分離して運用してください。

## 3. 実装ノート（仕様が定めない境界の解釈記録）

spec.md の「推測実装の禁止」に基づき、仕様が明示しない境界条件について採用した解釈を記録します（spec v1.0.1 変更履歴から参照）。

| # | 論点 | 採用した解釈 | 理由 |
|---|---|---|---|
| 1 | 予測用の日次系列の範囲 | **各SKUの初売上日〜全データ最終日**を連続日でゼロ埋め | 途中投入商品の平均が導入前ゼロで不当に下がるのを防ぐ |
| 2 | 実績7日以上だがホールドアウトを引くと学習7日未満になる場合 | バックテスト省略の**「参考値」**として全期間MAで予測（σ＝系列の標準偏差で保守的に代用）し、バッジ表示 | 予測を止めるより「根拠の弱さを明示して出す」方が現場価値が高い |
| 3 | 「全SKU合計」チャートの予測重ね | ホールドアウト予測の重ねは**SKU選択時のみ**。合計表示は実績＋将来合計 | SKUごとにホールドアウト長が異なり、合計側の重ねは誤解を生むため |
| 4 | 取込時の「上書き」の単位 | **（日付, SKU）ペア単位**で置換（日単位の全消しはしない） | 一部SKUだけのCSVを取り込んでも他SKUの同日実績を消さない（非破壊原則） |

## 5. 既知の制約・次版への提案

- **R-2 欠品バイアス**：実績＝需要とみなすため、欠品日があるSKUは過小予測になります（ダッシュボードに注記表示済み）。欠品フラグ入力はP1候補。
- **CHG-01（提案・未承認）**：`df_sales` の保存表現を圧縮形式（例：日付ごとの `"pid:qty"` 連結文字列）へ変更すると、保守換算でも約1/2に圧縮でき、UTF-16基準でもD-5を満たせます。**spec §6 の保存スキーマ変更に当たるため、承認後にv1.1で実施**します。現版でも4MB超過時は設定画面で警告＋退避案内が作動します。
- 本番URL・プロダクト名称・ブランドカラーは未確定（spec §8 未決事項）。
